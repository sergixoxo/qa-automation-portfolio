
# BUG-003 — Checkout Allowed with an Empty Cart

**Status:** Reproduced — Potential defect\
**Module:** Shopping Cart and Checkout\
**Environment:** SauceDemo\
**Affected user:** `standard_user`\
**Related User Story:** US-001\
**Acceptance Criterion:** CA-06\
**Related Test Case:** TC-006

## Description

The system allows customers to complete a purchase
without adding any products to the shopping cart.

## Preconditions

- Access to https://www.saucedemo.com/
- Login with `standard_user` and the password `secret_sauce`.
- The shopping cart is empty.

## Steps to Reproduce

1. Navigate to SauceDemo.
2. Log in using `standard_user`.
3. Open the shopping cart without adding any products.
4. Verify that the shopping cart is empty.
5. Click "Checkout".
6. Enter valid customer information.
7. Click "Continue".
8. Click "Finish".

## Expected Result

The system should prevent the customer from completing
a purchase with an empty shopping cart.

## Actual Result

The system allows the customer to complete the purchase
without any products in the shopping cart.

## Severity

Medium — Proposed.

## Severity Justification

The issue affects the checkout process but does not
prevent customers from completing regular purchases.

In a real e-commerce environment, this behavior could
generate invalid orders and inconsistencies in sales
reports or administrative processes.

## Manual Test Evidence

**Test case:** TC-006.\
**Execution type:** Manual.\
**Test result:** FAILED.

The application allows the customer to complete
a purchase with an empty shopping cart.

## Automated Test Evidence

**Automated test:** `test_checkout_with_empty_cart`\
**Framework:** Playwright and Pytest.\
**Initial test result:** FAILED.\
**Current test result:** XFAIL.

The automated test verifies that the shopping cart
and checkout overview contain zero products before
attempting to complete the purchase.

**Expected result:** The purchase confirmation
should not be displayed.

**Actual result:** The application displays the
following confirmation message:

`Thank you for your order!`

### Synchronization Strategy

An intermittent test result was identified during
headless execution due to asynchronous rendering.

The test was stabilized by replacing the immediate
negative visibility assertion with a conditional
wait for the purchase confirmation.

The test uses:

- Explicit element visibility synchronization.
- A maximum observation timeout of 5000 ms.
- Specific Playwright timeout exception handling.
- `pytest.mark.xfail` with `strict=True`.
- `raises=pytest.fail.Exception` to restrict expected failures.

### Stability Validation

Five consecutive isolated executions returned
the expected XFAIL result.

The complete regression suite also executed
successfully:

- Total: 20 tests.
- Passed: 17.
- Expected failures: 3.
- Unexpected failures: 0.

### Known Limitations

The absence of a purchase confirmation within
5000 ms does not independently prove that checkout
was correctly rejected.

An explicit rejection signal would be required
to fully validate a future defect correction.

The current implementation is intended to
reliably reproduce the observed defect.
